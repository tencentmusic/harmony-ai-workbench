# 设备结论不阻塞提测

1. 将设备结束结论与 Harness 严格 `delivery_ready` 分开，结论绑定当前构建、材料版本和验证报告 SHA256。
2. 在工作台状态、列表、设备页和提测交接中展示未完成结论；自动发布带真实结论的特性分支。
3. 发布前重验代码审查、构建和报告摘要；未完成任务不复用严格 finalize 文档，也不自动知识回流。
4. 覆盖结论绑定、分支文档、状态流转和既有严格通过路径，运行类型、架构和云 Agent 测试。
5. 测试服回归发现未登记额外 HEAD 的工作区被错误拒绝。结论改用现有 `harmonyHeadSha ?? baseSha` 规则；补充基线 HEAD、未提交源码变更的真实分支发布测试，以及显式 HEAD 不匹配的拒绝测试。
