# 设备验收结论与提测流转

## 行为

- 设备验收以当前材料版本、源码构建及原始验证报告为边界。代码审查和构建通过后，本轮设备执行结束时形成通过或未完成结论；未通过、缺样本、缺动态证据、视觉待决定等均如实列入结论。
- 未完成结论不改变 Harness 原生门禁或设备场景结果，也不表示 `delivery_ready`。工作台进入提测，自动发布附结论的特性分支，开发在本地复核、修复和验收后确认提测。
- 严格交付通过仍使用 Harness finalize 的四文档。未完成结论的分支仅归档设备结论及其绑定的报告摘要；代码合入后不自动发布宣称通过的知识文档。
- 构建、代码审查、材料版本或源码绑定失效时不能发布分支。未确认的设备操作继续保留原始收据，不补写通过证据。
- 源码 HEAD 与现有工作区校验一致：有登记的 `harmonyHeadSha` 时使用该提交，否则使用 `baseSha`。未产生额外提交的工作树也能形成结论；发布前仍校验真实分支与 HEAD，并把工作树变更纳入交付快照。

## 验收

设备验收与提测页面统一展示结论：真实结果、结构化分项状态、有序的结论与待办。
历史长文本仅按记录分隔符拆分、合并相同条目；不改变失败尝试、否定语句或恢复条件。
原始结论与门禁记录、材料版本、源码 HEAD、HAP 和报告 SHA256 保留在可展开区域，
展示整理不改写保存的结论或验收状态。实现记录见[展示整理](../plans/2026-10-16-device-conclusion-display.md)。

1. 设备阶段结束后，未通过任务显示结论、阻塞原因、构建与验证报告摘要，并进入提测。
2. 分支文档、集成单明确注明未完成项；开发确认提测不改写原结论。
3. 严格通过任务沿用原四文档与知识回流路径；未完成任务不生成四文档或知识 MR。
